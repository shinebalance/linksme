# リンクサイト 静的Webサイト（Vue3） 要件定義 & 実装方針（Draft）

## 0. 目的 / 成功条件

### 目的
- YouTube / ニコニコ動画 / Spotify など、自作音楽成果物へのリンクを**集約**する1ページを作り、**X（旧Twitter）のプロフィールに掲載**する。

### 成功条件（KPIの代替）
- Xプロフィール → 本サイト → 訪問者が自分の使っているサービス（YouTube/Spotify等）へ**迷わず遷移できる**こと。
- 想定訪問者：初見ユーザー（はじめて見る人）。

---

## 1. 運用 / ホスティング / 前提

### 運用期間
- URLは固定で**長期運用**。

### 更新頻度 / 更新方法
- 更新頻度：月1回あれば良い方（滅多に更新しない）。
- 更新方法：**コード直接編集でOK**。
- ただし `profile / links / OGPテキスト` は、ビルド前に**所定のMarkdownに記述**し、ビルドに反映される方式にしたい。

### 静的の定義
- APIコールなし（ランタイムで外部APIを叩かない）。
- ビルド成果物を静的ホスティングへデプロイ。
- ホスティング候補：Cloudflare Pages（主） / GitHub Pages（副）。
- 独自ドメイン：使わない。

---

## 2. 機能要求（Must / Should / Could）

### Must（必須）
- **1ページ完結**（複数ページ不要）
- 表示要素：
  - プロフィール（アイコン / 表示名 / 自己紹介）
  - リンク一覧（多数のサービスに対応：YouTube / ニコニコ / X / SoundCloud / Spotify / Apple Music / Amazon Music …将来追加可）
- リンクの見せ方：
  - **アイコン + ラベル**（ミニマル優先）
  - 表示順は固定（優先順をコード/Markdownで管理）
- リンク挙動：
  - クリックで**新規タブで開く**
- ダーク/ライト切替：
  - **テーマ配色はA**（サイト全体の配色がライト/ダークで切り替わる）
  - ユーザー選択を `localStorage` に保存
  - 初期値は OS設定（`prefers-color-scheme`）を反映
- GA4：
  - 最低限 **GA4タグを埋め込める**（ページビュー計測）
- OGP：
  - `og:title`, `og:description`, `og:image`, `og:url`
  - `twitter:card` 等、Xのカード表示を意識
- favicon：
  - 設置する
- パフォーマンス：
  - スマホ/PC両対応
  - できるだけ軽量（外部依存を増やさない）

### Should（できれば）
- クリックでコピー：
  - **URLをコピー**できる（リンクごとにCopyボタン）
  - 成功/失敗のフィードバック（軽いトースト等）

### Could（将来）
- リンクカテゴリ分け（増えた場合）
- 固定バナー（期間限定告知）※現時点では不要

### Not required（不要）
- SNS埋め込み：**なし**
- 言語切り替え：なし
- 期間限定の告知枠：不要
- 厳密なアクセシビリティ要件：なし（ただし基本の可読性は確保）

## 3. コンテンツ管理（Markdown駆動）

### 必要なMarkdown（所定の場所）
- `content/profile.md`
- `content/links.md`
- `content/seo.md`（OGP/SEOテキスト）

### 期待する挙動
- これらMarkdownを編集してビルドすると、**サイト内容に反映**される（ランタイム読み込みではなくビルド時取り込み）。

---

## 4. アイコン要件（ライト/ダーク2種）

- 各サービスアイコンは **Light用 / Dark用の2種類**がすでに存在。
- テーマに応じて自動出し分け：
  - lightテーマ → lightアイコン
  - darkテーマ → darkアイコン
- 例）配置案：
  - `src/assets/icons/light/*.svg`
  - `src/assets/icons/dark/*.svg`

---

## 5. 実装方針（Vue3 + Vite / Static）

### 推奨パターン
- **A案（推奨）：Vite + `import.meta.glob(..., { as: 'raw' })` + 自前パーサ**
  - 依存が少なく静的運用に安定
  - Markdownを任意フォーマットにできる
- B案：frontmatter（gray-matter + markdown-it）
  - 記事用途には強いが依存が増える

本プロジェクトでは **A案**で進める。

## 6. Markdownフォーマット案（Draft）

### `content/profile.md`（例）
- 目的：プロフィール表示（表示名 / タグライン / アイコン）

例：

    # shineloops
    MINIMAL / COOL / VOCALOID

    ![avatar](../public/avatar.png)

ルール案：
- 1行目（`# ...`）：表示名
- 2行目：短いタグライン（任意）
- 画像：任意（`public/avatar.png` を運用上のデフォルトに）

### `content/links.md`（例）
- 目的：リンク一覧（アイコン種別・ID・順序を含む）

例：

    - [YouTube](https://youtube.com/@xxxx) {id=yt icon=youtube}
    - [ニコニコ動画](https://www.nicovideo.jp/user/xxxx) {id=nico icon=niconico}
    - [X](https://x.com/xxxx) {id=x icon=x}
    - [SoundCloud](https://soundcloud.com/xxxx) {id=sc icon=soundcloud}
    - [Spotify](https://open.spotify.com/artist/xxxx) {id=sp icon=spotify}
    - [Apple Music](https://music.apple.com/xx/artist/xxxx) {id=am icon=applemusic}
    - [Amazon Music](https://music.amazon.co.jp/artists/xxxx) {id=az icon=amazonmusic}

ルール案：
- `[]()` は人間が読めるMarkdown
- `{...}` はビルド時にパースして `id` / `icon` を抽出
- `id` は将来のGA4イベント等へ拡張しやすい
- 表示順は記述順を採用（または `priority` 属性を追加しても良い）

### `content/seo.md`（例）
- 目的：SEO/OGPテキスト管理（1ページ分）

例：

    title: shineloops | links
    description: Vocaloid / original tracks. Links to YouTube, NicoNico, Spotify and more.
    ogImage: /ogp.png

ルール案：
- key:value形式で軽量に管理（1行1キー）

## 7. 実装上のポイント

### 7.1 ビルド時Markdown取り込み
- `src/content/loadContent.ts` で `content/*.md` を raw import
- 自前パースして構造化：
  - `profile.md` → `{ name, tagline, avatarPath? }`
  - `links.md` → `LinkItem[]`
  - `seo.md` → `{ title, description, ogImage }`
- Vueは構造化されたデータを表示するだけ（ランタイム依存なし）

### 7.2 テーマ切替（配色A）
- `html` または `body` に `data-theme="light|dark"` を付与
- CSS変数（`--bg`, `--fg`, `--muted`, `--card` など）で全体配色を切り替え
- 初期テーマ：
  - `localStorage` があればそれを採用
  - なければ `prefers-color-scheme` を採用
- 変更時：
  - `data-theme` 更新
  - `localStorage` 保存
  - アイコン参照先も切替（light/dark）

### 7.3 リンクUI（アイコン + ラベル）
- リンクはボタン/カード状で統一
- ホバー時に最低限のアニメーション（視認性向上）
- クリックで新規タブ：
  - `target="_blank"` + `rel="noopener noreferrer"`

### 7.4 コピー（URL）
- 各リンク行に「Copy」ボタン（またはアイコンボタン）
- `navigator.clipboard.writeText(url)` でURLをコピー
- 成功/失敗の軽いフィードバック（トースト/スナックバー）

### 7.5 GA4
- `index.html` にGA4タグを埋め込み（ページビュー計測）
- 測定IDは将来差し替えやすくする余地：
  - 直書き or 環境変数（Cloudflare Pages）で注入

### 7.6 OGP/SEO（Markdown反映）
- 静的1ページのため、`index.html` にOGP metaを出すのが確実
- `seo.md` の内容を **ビルド時に index.html へ注入**する（Viteプラグイン等）
  - もしくは最初は直書きで開始し、後から注入に移行しても良い（ただし要件的には注入が本命）

## 9. 既知の制約 / 方針

- 外部埋め込み（YouTube/Spotify iframe）は**使わない**（軽量優先）
- 計測はGA4タグ埋め込みが最低限（サイト内で高度な分析は不要）
